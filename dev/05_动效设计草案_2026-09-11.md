## 二、现状盘点（探查完成）

- **动效底子**：仅零散 CSS transition（hover 背景/阴影/透明度，全部 0.15~0.2s）；**0 个 @keyframes / animation**；rAF 已有 2 处（画布移动阻尼惯性 v6.1、方向键平滑加速 v6.17）——结构上"动效"的骨架完全空缺，从零设计。
- **已有视觉资产（可动的素材）**：拼入光线（SVG 贝塞尔渐变光线，静态）、拖手光点（蓝紫 radial 渐变，静态）、毛玻璃（backdrop-filter）、极淡阴影分层、macOS 浅色视觉（--card/--accent/--border CSS 变量体系已就位，可挂动效 token）。
- **代码结构**：CSS 190 行 / JS ~1840 行 / 单文件 116KB。交互点完备（块生命周期 / 拖拽 rAF / 拼入 / 窗口 / 光线 / 缩放 / 一键整理 / toast / 多选 / 右键菜单）。
- **用户底线（红线，动效不得触碰）**：
  1. **拖拽跟手即时性**——重度拖拽用户，拖块/平移/缩放跟手 0 延迟（拖拽路径全部即时 transform，不许加 transition）；
  2. **极简 UI 不增按钮**——动效只用 CSS/JS 实现，不新增任何 UI 控件/设置项；
  3. **数据/画布语义零改动**——动效只动"显示层"，坐标、拼接逻辑、持久化原样。

## 三、设计基调（三选一，待用户拍板）

| 选项 | 风格 | 适配 | 体积/性能成本 |
|---|---|---|---|
| **A. macOS 原生克制风** | 只在"反馈"处动（hover/按下/出现），叙事动画全部不做；与现有 macOS 浅色视觉同源 | 最稳、最省 | 增量 ≤2KB |
| **B. 灵动精致风 ⭐推荐** | 反馈动效全做 + 关键叙事动画做足（块弹入/删除、一键整理排布、拼入吸入+光线流动、窗口开合、toast 滑入），曲线用 premium ease-out | 与"全面设计高质感动效"诉求最匹配；收益/风险比最优 | 增量 ≤7KB |
| **C. 活泼表现风** | 在 B 基础上加弹簧 overshoot、光晕呼吸、背景光斑漂移、缩放平滑 | 动效成产品记忆点 | 增量 >10KB，与极简偏好冲突风险高 |

**推荐 B**：四个字"全面设计"对应的正是 B 的系统化（反馈层+叙事层全覆盖）；C 的弹簧/漂移类在工具型单文件里易腻、易显廉价，且与"极简、纯粹"拍板史冲突。

## 五、技术设计

- **手法分层**（按场景选，不混用）：
  - `transition` 兜底 90% 场景（状态切换：hover/press/出现/消失）；
  - `@keyframes` 仅 2 处：drop-target 光晕呼吸、背景光斑漂移（P2 可选）；
  - `FLIP` 实现一键整理（唯一需要 JS 算位的动画：旧位快照 → render → 新位过渡 → transitionend 清 inline）；
  - **rAF 既有循环不碰**（拖拽/方向键/惯性已即时，动效不得叠加）。
- **合成器铁律**：所有动画只动 `transform` + `opacity`（GPU 合成零重排）；box-shadow 动画仅 hover/press 级小面积使用；光线流动用 `stroke-dashoffset`（SVG 合成属性）。
- **性能预算**：任意时刻活动动画 ≤ 8 个（一键整理 20+ 块时用 block 内错峰，单帧最多 ~4 个块在动）；不引入 JS 动画库（66KB 体积代价 + 单文件零依赖原则）。
- **体积预算**：CSS 新增 ≤3KB + JS 新增 ≤4KB ≈ **总增量 ≤7KB**（116→≤123KB）。实施时按此预算分配，P2 项先做先量，超支即砍。
- **无障碍兜底**：`@media (prefers-reduced-motion: reduce)` 全部叙事动画降级为 0ms 直切（块完成、功能不变）；不新增 UI 开关（不算新控件入 UI）。
- **不触碰红线**：拖拽/平移/缩放跟手 0 延迟；无新按钮/设置项；坐标与数据模型零改动；sanitizeState/持久化不动。

## 六、设计基准（联网收集速查，实施时对照）

| 场景 | 时长 | 曲线 |
|---|---|---|
| 简单反馈（toggle/checkbox） | ~100ms | — |
| hover 颜色/浮起 | 100–150ms | standard |
| 元素进入（出现） | 150–250ms | decelerate: `cubic-bezier(0,0,.2,1)` |
| 元素离开（消失） | 120–200ms | accelerate: `cubic-bezier(.4,0,1,1)` |
| 状态间移动（整理/排布） | 250–350ms | premium ease-out: `cubic-bezier(.16,1,.3,1)` 或 M3 emphasized |
| 面板/窗口滑入 | 240–300ms | decelerate |
| 成功反馈（点赞类） | 350–450ms | overshoot 弹簧 |
| ⚠️ 超过 500ms 不是曲线问题，是时长错了 | | |

要点：**曲线比时长更决定"质感"**（linear=机械感）；进入用非对称减速、离开用加速；用户主动触发的反馈要快（~100ms 体感即时），系统叙事的可稍长（≤350ms 封顶）。
