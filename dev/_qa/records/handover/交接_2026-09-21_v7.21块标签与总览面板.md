## 三、根因与修法

### 3.1 ★真实回归：R3-A 皮肤词元棘轮（不是那个已知 flake）

第二次跑闸门 `[6] verify_v78` 报 **53/54**。`HANDOVER` 恰好记着「`verify_v78` 偶发红（1/3）」——**最容易的错就是把它当 flake 放过**。
按 **T9「先稳定复现、不许假设」**取明细：

```
FAIL  R3-A 皮肤词元棘轮：命中 16 ≤ golden 15      命中词元=[… "全景" …]
```

**根因**：面板最初命名「项目**全景**」，而 **`skin/corpus.js:67` 有 `{ label: '全景' }` —— 「全景」是领域词元（景别词）**。把它写进引擎代码（`view/modals.js` + `index.html`）= **E6 要防的场景**，棘轮 15 → 16。
**修法**：改名「**总览**」（皮肤语料零出现，已验证），并在 `index.html` 就地写下命名避坑注释。
**结论**：这条断言**真的在工作**——它挡住的是「引擎混入领域语义」的渐进腐蚀。

### 3.2 ★需求一的致命点：新字段会被静默剥离

`core/persist.js` 的 `migrateBlocks()` 末尾用**固定投影**重建块对象。若只加字段而不改投影，`tag` 会在**每次 load 时静默消失且不报错**。
**修法**：**两处**投影（中间对象 + 末尾 map）都纳入 `tag`，脏值/缺失归 `''`。已由 `verify_v721` **A1/A2** 守门（A2 做**真实 reload** 往返）。

### 3.3 ★被证伪环节抓出的**我自己的套件缺陷**

证伪 R2 把组头改成 `.wd-item` 后，助手 `__rowInfo` 对无 `.wd-no` 的行直接 `null.textContent` → **套件崩溃（exit 1）**，run-gate 报「未取到汇总」而非逐条红。
**修法**：断言应**报红而非崩掉** → 为 `__rowInfo` 与 B5 的 `tdSel` 加**空值防护**。**该缺陷是被证伪发现的，不是被"测试通过"发现的。**

### 3.4 ★证伪需正确的准备条件（工艺）

直接改坏源码会让 `[1]/[2]` 先红、**下游闸门根本不执行**，因而**触达不到 [16]**。
→ **闸门级证伪的正确做法**：改坏并重建后，**同时把破坏版刷新为等价基线**（拷入快照），使 `[2]` 通过，才能让 `[16]` 真正跑到并退**自己那道**的码。本轮 R1 首次尝试即踩到这个坑。
