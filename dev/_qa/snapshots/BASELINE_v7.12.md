## 本轮变更要点（v7.11 → v7.12 · R0 清债）

### 1. 问题：每个模块都残留了 P2 时代的死导出行

P2 阶段的导出面是「**全部顶层符号**」，P3 收敛为「**被他模块引用的顶层名**」时，**旧的 P2 导出行被保留下来、
与新行并存**——形成"同一模块两次 `PHJ.x = {…}`"的形态（16/17 个模块命中，唯一例外是 `shell/head.js`，
它只有一条导出行）。后一条**覆盖**前一条，所以**运行期无害**，但：

- 读者看到两条导出面，**无法判断哪条是有效的**（真实耦合被掩盖）
- 源码里留了一段**已退役的架构决策**，属于"源码只留生效态"原则的违背（Q11 拍板）

### 2. 解法：删旧留新，纯减法

对 16 个模块删除 P2 那条死导出行及其标题注释，保留 P3 的客观统计导出面。改后：

- 单模块**恰好一条** `PHJ.<module> = { … }`
- 自包含模块（`interact/keys`、`interact/paste`）写作 `PHJ.keys = {}` / `PHJ.paste = {}`

## 新增断言：P2-B2 导出面内容契约

R0 的证伪测试**暴露了一条真实断言漏洞**：原 `P2-B` 只断言「`PHJ` 有 16 个模块键」，
把 `PHJ.struct = {}` 清空**依然 PASS** —— 它守不住导出面的**内容**。

补 `P2-B2`：以 `P2_EXPORTS_GOLDEN` 常量逐模块列出**全部 108 个导出名**，逐名精确比对。
**证伪证据**：注入 `PHJ.struct = {}` 后 → `P2-B` PASS / **`P2-B2` FAIL**（`不符模块=[["struct",[]]]`）、
退出码 1；还原后 50/50 全绿、产物指纹复原。
