# 环境探测与工装陷阱（2026-09-20 · v7.20 期建立）

> 本文档**只写探测方法与陷阱清单，不写死任何机器的绝对路径**——换机/换 agent 管理区时按本文逐项探测，把探测结果记在当次会话里即可。
> 适用：Windows + WorkBuddy/沙箱类 agent 环境；其他平台按同理替换。

## 1. Shell 与 unix 工具

**现象**：部分环境的 bash（便携版 Git Bash）**PATH 缺 unix 工具**（`ls`/`grep`/`sed`/`cat` 可能直接 `command not found`）。

**探测方法**：
```bash
which ls grep sed cat find   # 逐个试；缺哪个补哪个
```
**修法**：找 agent 运行时自带的便携版工具链（WorkBuddy 环境在 `~/.workbuddy/binaries/` 下有 **PortableGit**（含 `mingw64/bin`、`usr/bin`）与**受管 node**），把它们的 bin 目录前置到 PATH：
```bash
export PATH="<便携版Git>/mingw64/bin:<便携版Git>/usr/bin:<受管node目录>:$PATH"
```
★每条命令前都要带（shell 状态不跨调用持久）。

## 2. git

**现象**：本机 PATH 可能**没有 git**（`git` → exit 127）。

**探测方法**：先试 `git --version`；失败则找便携版：`ls ~/.workbuddy/binaries/*/cmd/git.exe` 一类位置；用**全路径**调用即可，无需安装。

**本机已知坑**：Git for Windows **创建含 `/` 的 ref（分支/tag）可能静默失败**（exit 0 但 ref 不存在）→ **打 tag/建分支后必须 `git show-ref` 复核**（删除正常）。

## 3. node

**现象**：`node` 可能不在 PATH，或版本不对。

**探测方法**：`node --version`；失败则在 agent 运行时的 binaries 目录下找受管版本（如 `~/.workbuddy/binaries/node/versions/*`）。构建要求：纯 node 零依赖，任何较新版本皆可（本机实测 22.x）。

## 4. 闸门与浏览器

- `node dev/_qa/run-gate.mjs` **自起自收** headless 浏览器（约 100s）：自动探测 Edge/Chrome、选空闲端口（起始 9222，被占则顺延）、跑完 15 道杀进程。
- **单独跑某个套件**时需自备调试浏览器（起 `--remote-debugging-port=9222`），或先跑一次 run-gate 复用；否则报 `ECONNREFUSED 127.0.0.1:9222` 是**预期**不是缺陷。
- ★工具调用结束会**回收子进程** → 手动起浏览器必须与跑断言在**同一次工具调用**内完成。
- 浏览器 exe 可用环境变量 `PHJ_BROWSER` 硬覆盖；端口经 `PHJ_BROWSER_PORT` 传给套件。

## 5. stdout 采集陷阱

**现象**：部分环境的 **PowerShell stdout 偶发为空**（命令 exit 0 但拿不到输出）；Bash 也偶发。

**取证替代法**（按序降级）：
1. 优先用 Bash；
2. Bash 也空 → 命令输出**重定向到文件** + 用读文件工具读回（临时文件用后删除）；
3. 判定类结论**不要依赖 stdout**，改读磁盘物证（文件存在性/内容/git show-ref）。

## 6. 沙箱删除阈值

**现象**：一个 turn 内累计删除文件数触顶（实测 ≈50）→ **整条删除命令被拒**（提示"用户已拒绝"），且系统要求**不得重试或换等效手段**。

**规避**：清理临时文件时用**明确路径逐个列出**（勿用通配符）、**单批 ≤10 个**、删完立即复核；**换一个 turn 计数即重置**。`AppData` 下的一律不擅自递归删除（安全禁区）。

## 7. headless CDP 限制（影响测试写法）

| 限制 | 影响 | 替代写法 |
|---|---|---|
| **鼠标拖选不派发选区**（v7.19 实测，纯 textarea 对照证实） | 划选类断言不能依赖 `Input.dispatchMouseEvent` press→move→release | 「点击起点 + **Shift+点选**延展」——同一 DOM 选区路径 |
| `Page.navigate` 后旧页本就 `complete` | 只等 readyState 会立即 break（在错页上跑） | 等待条件加「`location.href` 已落在目标」或重试（见 verify_v719） |
| 跨进程时钟 1ms 级偏差 | node 侧 `Date.now()` 框浏览器侧时间戳会随机假红 | 时间基准与被测值**同进程**取（`await evalJS('Date.now()')`） |

## 8. 会话级注意事项（agent 运行环境）

- **临时文件**：探针/截图/dump 用后必删；仓库有 `.gitignore` 规则 `dev/_qa/_*`，但 `diag/` 子目录不覆盖 → 放 `dev/_qa/` 顶层的临时物提交前必须清掉
- **会话中断**：agent 可能被中断/回收——**磁盘状态是唯一可信进度**（文件 mtime + git status），恢复后先查磁盘再决定续做还是重做
- **记忆位置**：agent 会话侧记忆（`.workbuddy/memory/`）只作**指针**，项目事实以仓库内 `PROJECT_MEMORY.md` 为准——**不要把项目知识只写进会话记忆**

## 9. Linux 巡回（Windows ↔ Linux 跨平台 · 2026-09-20 起支持）

> 目标：项目允许在 Windows 与 Linux 的 agent 管理区之间自由巡回（多 agent 异步开发）。
> 产品与构建天然跨平台（纯 node + 单文件 HTML）；闸门工装已做平台适配（浏览器探测
> win32/darwin/linux 三平台候选 + `PHJ_BROWSER` 硬覆盖 + `PHJ_BROWSER_FLAGS` 注入点 +
> root 自动 `--no-sandbox`；套件 URL 统一 `pathToFileURL`）。**Linux 侧 agent 的首次接手
> 就是跨平台的最终验收**——按下面清单走，跑完闸门 15/15 即完成首巡回，并在 HANDOVER.md
> 记录「已巡回平台」。

### 9.1 依赖探测（Linux）

| 依赖 | 探测 | 备注 |
|---|---|---|
| git / node / bash 工具链 | `git --version; node --version` | Linux 通常系统自带，无便携版问题 |
| 浏览器 | `for b in microsoft-edge microsoft-edge-stable google-chrome google-chrome-stable chromium chromium-browser; do command -v $b; done` | 探测不到 → 安装任一（`apt install chromium` 等）或 `export PHJ_BROWSER=/绝对路径`（**硬覆盖**，只认它） |
| **CJK 字体**（★像素断言的前提） | `fc-list :lang=zh \| head -3` | **空 = 没有中文字体 → verify_v719/v720 的像素断言必假红**（文字渲染成豆腐）。安装：`apt install fonts-noto-cjk` |
| Chromium 版本 | `chromium --version` | `--headless=new` 要求 ≥109；更老 → 换新浏览器并用 `PHJ_BROWSER` 指定 |

### 9.2 已知的 Linux 差异（已适配/需注意）

- **root/容器**：Chromium 无 `--no-sandbox` 拒绝启动 → run-gate **自动追加**（root 时）；也可 `PHJ_BROWSER_FLAGS="--no-sandbox"` 手动给。
- **文件锁**：Linux 无 Windows 文件锁问题，profile 清理干净利落（run-gate 的重试逻辑两平台通用）。
- **行尾**：git 在 Linux checkout 出 LF——已实测不影响产物字节（`build.mjs` 归一化 + 快照 `-text`），等价性跨平台成立。
- **字体渲染差异**：Linux 的 CJK 字体（Noto）与 Windows（雅黑）像素不同 → **像素断言的"阈值"跨平台通用，但墨迹颜色/数量会有微小差异**；若 v7.19/v7.20 组在 Linux 首巡回出现像素类假红，先查字体再怀疑产品。
- **Docker/CI**：镜像需含 node ≥18 + chromium + fonts-noto-cjk；以非 root 或 `--no-sandbox` 运行。

### 9.3 首次巡回验收清单（Linux agent 首接手时执行）

1. 按 `AGENTS.md` 接手 5 步（§9.1 探测并入第 3 步）
2. `node dev/_qa/run-gate.mjs` → **15/15 全绿**
3. 在 `HANDOVER.md` 的「已巡回平台」记录：平台 / 浏览器与版本 / 字体 / 闸门结果 / 日期
4. 若有平台特有假红 → 先查本节已知差异，确认是环境问题则**记录后用 `PHJ_BROWSER_FLAGS`/字体安装解决**，不许改断言判定式

## 10. Shell 引号陷阱（传长文本给命令时必读）

**现象**：把多行 / 含特殊字符的长文本直接内联进 shell 命令（如 `git commit -m "..."`），
文本里的**英文直双引号 `"`** 会**提前闭合字符串** → 参数被重组：实测提交消息**被截断在半句**，
后半截被当成命令执行（报 `No such file or directory`），而 `git commit` 本身**成功**——
**症状不指向根因**（消息坏了但提交看起来正常）。

**铁律**：一切长文本（提交消息 / 补丁 / 配置 / 脚本）**一律落到文件再引用**：
- `git commit -F <消息文件>`（或 `--amend -F`）——**禁止用 `-m` 传多行消息**
- `node <脚本.mjs>` —— 禁止 `node -e "…"`（反引号会被 shell 当命令替换吃掉，另一个同类坑）
- 写文件用编辑器/写文件工具，不要 `echo "…" > f` 拼长内容

**自查**：消息/文本写完先读回确认（`git log -1 --format=%B | wc -l` 与末几行）。

## 11. 表格类文件的行级编辑（追加行时）

用「上一行」做锚点插入新行时，**锚点行必须原样包含在新内容里**——否则整行被替换掉、
历史记录静默丢失（实测：变更记录表追加两条时覆盖了中间一条，靠 `tail` 复核才发现）。
改完**必须复核该区段全文**，不只看新增行。
