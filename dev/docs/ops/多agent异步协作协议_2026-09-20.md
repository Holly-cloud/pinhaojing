# 多 agent 异步协作协议（拼好镜 PHJ · 2026-09-20 定稿）

> ★**本协议中的约束条文以 `IRON_RULES.md` 为准**（C1-C6 协作铁律 / T1-T11 测试铁律）；
> 本文件负责流程与角色（怎么协作），铁律负责不可让步的底线（什么不能做）。
> 目的：让项目**随时可以在多个 agent 的管理区域之间频繁转移**——任何 agent 在任何会话里
> clone/打开仓库，按协议走，即可无缝接手或交出，不依赖任何一个 agent 的私有记忆。
> 本协议由 2026-09-17 ~ 09-20 四轮（v7.17→v7.20）多 agent 实战验证后固化。

## 一、核心原则

1. **仓库即协作总线**：协作状态（口径/裁决/进度/教训）的全部持久层在 **git 仓库内**；
   agent 会话侧记忆只作指针，**禁止把项目知识只写进会话记忆**。
2. **闸门即契约**：`node dev/_qa/run-gate.mjs` 15/15 全绿 = 唯一的"工作正常"定义。
   交接、续作、收尾，一律以闸门为准，不以任何人的口述为准。
3. **跨成员信息流必须经主理人**：工程师/QA/架构师/产品经理互不直连；
   主理人负责分派、裁决、汇编与中转。
4. **磁盘状态是唯一可信进度**：会话可能随时被中断/回收——恢复后先查
   `git status` + 文件 mtime，判断续做还是重做，**不要假设上次工作还在内存里**。

## 二、角色与职责

| 角色 | 职责 | 产出 |
|---|---|---|
| **主理人**（齐活林） | 需求澄清、口径裁决、任务分派、信息中转、汇编交付、**唯一 commit/push 人** | 任务书、裁决、交付汇报 |
| **工程师**（寇豆码） | 按任务书实现；完成后全局一致性审查 | 代码 + diff 说明 + IS_PASS |
| **QA**（严过关） | 独立验证（不采信工程师自述）；常驻断言建议 | 复验报告 + 智能路由判定 |
| **架构师**（高见远） | 数据模型/架构设计 + 根因调查 + 任务分解 | 设计文档 + 任务列表 |
| **产品经理**（许清楚） | PRD / 需求分析（中大型需求才启用） | PRD |

智能路由判定（QA 每轮必给）：`Engineer`（源码 bug）/ `QA`（测试自身 bug，自修）/ `NoOne`（全过）。

## 三、任务书要素（主理人派单必含）

1. **环境**：仓库根、PATH 探测指引（指向《环境探测与工装陷阱》）、「可否自由跑闸门」
2. **当前基线**：版本 / 产物体积 / sha256 / 闸门形态 / HEAD 与 tag
3. **需求口径表**：逐项列明已拍板的口径（**标明不可变更项**）
4. **红线**：引用 PROJECT_MEMORY 的红线 + 本轮特有约束
5. **完成判据**：build / 闸门 / skin-guard / 真机自测场景（含反面对照）
6. **纪律**：❌ 不 commit/push（主理人统一提交）；✅ 临时物清理；✅ 全中文；IS_PASS
7. **回报格式**：TL;DR / 改动清单（文件:行）/ 闸门逐项 / 自测证据 / 遗留

## 四、QA 铁律

★**条文见 `IRON_RULES.md` T1-T11**（本文件不再复制）。本节只留流程性说明：

- QA 每轮必给**智能路由判定**（见 §二）；每轮测试最多 2 轮，2 轮不过则输出报告并标注遗留问题；
- QA 只写 `dev/_qa/**`，**不改产品源码**（发现源码 bug → 报主理人转工程师）；改坏/证伪必须用**产物副本**，验完清理；
- 常驻断言升格须**先报 Holly 核准条数**（T4）。

## 五、交接 checklist

### 接手方（新 agent）5 步

1. 读根 `AGENTS.md` → 2. 读 `HANDOVER.md` → 3. 读 `dev/docs/ops/PROJECT_MEMORY.md` +
   《环境探测与工装陷阱》逐项探测 → 4. 跑 `node dev/_qa/run-gate.mjs` **必须 15/15** →
   5. 读 `dev/_qa/records/handover/` 最近 2-3 份档案（理解近期口径与未决项）。
   **任一步不满足 → 停下来向交出方/用户追问，不带病开工。**

### 交出方 3 步

1. **更新 `HANDOVER.md`**（版本/指纹/闸门形态/在途工作/待裁决项/环境异常）；
2. `git status` 干净 + 闸门 15/15 全绿 + 提交（含 tag，若为版本交付）；
3. 把本轮任务书与回报**存档**到 `dev/_qa/records/handover/`（命名：`交接_<日期>_<主题>.md`）。

三者齐 = 交接闭环。

## 六、任务存档制（A4）

- 位置：`dev/_qa/records/handover/`；每轮需求交付后由主理人落一份**浓缩档案**
  （需求口径 / 关键裁决 / 根因与修法 / 遗留），不必逐字抄会话。
- 首批档案：`交接_2026-09-18至20_v7.17-v7.20四轮.md`（本协议建立前的四轮已补录）。
- 作用：新 agent 考古「为什么这么做」；避免重复踩已排过的坑。

## 七、版本交付节奏

- 需求实现 → 主理人独立核验 → QA 独立复验 → （新功能）常驻断言升格（条数报用户核准）→
  文档收口（CHANGELOG/README/HANDOVER）→ 主理人 commit + tag → 存档。
- 快照规则：新版本 = 新快照 + 新 BASELINE；实现期就地补丁 = **同名覆盖快照**（不新开版本）。
