## 一、背景：R1 只守住了「一条边」

R1（v7.13）把领域语料从 `editor/complete.js` 抽到 `skin/corpus.js`，并用一条断言守门：
**引擎（`core/`+`editor/`）不得引用 `skin/`**。但这条断言只堵**路径引用**——领域**词元**
可以被直接写成字面量塞进引擎代码，完全绕开它。事实上 R1 之后引擎里仍躺着：

- `editor/struct.js` 的 `STRUCT_MARKS`：`画面开始 / 画面结束 / 风格 / 硬性要求 / 【…】 / 镜头N`；
- `editor/complete.js` 的 `CMPL_GROUP_HINT`：`风格包 / 硬性要求 / 起手式 / 结构件 / 镜头句 / 景别 / 运镜 / 台词`；
- `core/store.js` 的默认示例块文本、`editor/library.js` 的占位符文案。

它们是「符号契约」（结构层/置顶评分按**符号**而非语义工作），**不是待清债**；但若没有量化边界，
「引擎零领域语义」就只是一句注释。

## 二、三项收口（本轮）

### R2 · `shell/boot.js` → `shell/wiring.js`（只改名不拆）

### R3 · 引擎零领域语义**棘轮**（新模块 `dev/_qa/lib/skin-guard.mjs`）

| 口径 | 内容 |
|---|---|
| `harvestDomainTokens(skinSrcFiles)` | 从**皮肤源码的字符串字面量**里抽领域词元（连续 CJK，长 ≥ 2） |
| `listEngineFiles(srcRoot)` | `src/**` 非皮肤 JS（排除 `skin/**` 与生成物 `dev-bundle.js`） |
| `DOMAIN_HITS_GOLDEN` | 冻结尾数 **15** |

- **R3-A 棘轮**：皮肤词元命中「引擎代码（**剥注释**）」的去重数 **≤ 15**。**只堵新增**——迁移出引擎不惩罚。
  为何剥注释：R3 说的是「引擎**代码**零领域语义」，引擎自己的文档注释不计入预算（与 R1 同源口径）。
- **R3-B 零泄漏**：皮肤**长语料**（≥ 40 字）在非皮肤源码**原文**里 **命中 == 0**（硬零容忍）。
- 实测：146 词元 → 命中 15（即上文那批符号契约）。

### R4 · 皮肤**可摘除**（逐字节证明 + 合成皮肤替换演练）

- 命题：产物内联 JS 段 == 「非皮肤片按构建规则拼接」+「皮肤片贡献」，且皮肤片可**整段摘除**
  （摘除后逐字节 == 非皮肤片拼接）→ 皮肤是**可替换的独立段**。
- 做法：真读 `PHJ.html` → LF 归一 → 剥 IIFE 外壳 → 按 `build.mjs` 规则反算；断言「减皮肤 == 非皮肤拼接」。
- 替换演练：用合成皮肤段替换真皮肤段后，引擎前缀/后缀**逐字节不变**。

## 三、为什么这样设计（取舍）

1. **棘轮而非 `== 0`**：现存符号契约是机制必经；`== 0` 会逼着为「符号→区」这类映射做无谓抽象。
   棘轮**冻结当前水位、只堵新增**——既守住方向，又不惩罚进步（命中减少不会红）。
2. **剥注释 vs 原文**：R3-A 判**代码**（剥注释），R3-B 判**原文**（更严）。两者合起来：
   代码里不许新增领域语义，连注释里出现长语料（内容）也算泄漏。
3. **R4 真读产物**：不做「源码层面自证」，而是拿**已构建的产物**去反证「它 = 非皮肤 + 皮肤」——
   这样 R4 同时是「产物 == 源码」的守门人（改任一源片不重建，R4 即红）。
4. **边界文档化**：`DOMAIN_HITS_GOLDEN` 维护口径**只减不增**；确需上调须在 BASELINE 写明理由。

- 证伪：下限临时抬到实测之上（词元 ≥ 999）→ R3-C **独红**；还原后 54/54。
