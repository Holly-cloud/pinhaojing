## 2. ★ Q7 需求：私有写作资产与通用产品代码的边界

### 2.1 问题（现状与证据）

| 事实 | 出处 |
|---|---|
| `CMPL_STYLE`（风格包 5 段全文，约 542 字符）+ `CMPL_TAIL`（硬性要求原文）**逐字硬编码进产品源码** | `dev/src/js/52-complete.js:20-27` |
| 作者**蓄意并自标注**：「逐字引用的只有你的『风格包』——那是项目级资产，不是片段」；该组标「项目级定型件」 | `52-complete.js:8-9, 36` |
| 违背 v7.6/v7.7 既定原则「**引擎零领域语义**」 | `dev/src/js/00-header.js`（v7.6 条目） |

**两个后果**：① 单文件一旦对外分发/分享 = **随码发布 Holly 的私有写作资产**；② 项目专属数据烧进通用产品代码，**产品通用性受损**。

### 2.2 产品目标

1. **可分发**：交付的 `PHJ.html` 不含任何真实用户的私有写作资产逐字文本。
2. **零退化**：Holly 的日常使用不受损——她的风格包仍然可用，且不因此变成"必须多带文件 / 必须联网"。
3. **可携带**：私有资产成为**可导出/可导入的用户数据**，与产品代码解耦。

### 2.3 用户故事（Holly 视角）

- **US1（分发）**：作为要把工具分享给别人的作者，我希望 `PHJ.html` 里不再含我的私有写作资产，这样分享出去不会连我的风格包一起发出去。
- **US2（日常）**：作为每天用风格包的人，我希望升级后打开工具、风格包还在（最多只需我在本机做**一次**导入），这样我不会因为这次改动丢资产。
- **US3（管理）**：作为使用者，我希望能在工具内**导入/导出**我的写作资产（本机文件，不走网络），这样我能换机/备份/替换，而不用改源码。
- **US4（维护）**：作为接手维护的工程师，我希望内置库只放**通用能力与中性示例**，让产品对任何人都通用、也不承担发布他人私有数据的责任。
- **US5（防误删）**：作为使用者，我希望「恢复内置默认」不会悄悄删掉我导入的资产。

### 2.4 边界定义（核心交付物）

| 随 `PHJ.html` 发布的**内置库** | **用户数据**（`localStorage` / 导出 JSON / 外部资产文件） |
|---|---|
| ✅ **应含**：通用写作能力——结构件 / 起手式 / 镜头句 / 景别 / 运镜 / 台词等**从规律提炼**的参数化片段与槽位；触发符 / 候选 / 槽位 / 配置窗口等**机制** | ✅ **可含**：Holly 的风格包 5 段 + 硬性要求原文；她新增/改写的任意片段（这是她的数据，非发布物） |
| ⚠️ **可含（须显式标注）**：明确标为「**示例（请替换）**」的**中性**示例数据，且不得是任何真实用户私有资产 | — |
| ❌ **不应含**：任何真实用户/项目**私有写作资产的逐字文本**（首当其冲 = 风格包 + 硬性要求） | — |

### 2.5 需求池

| 优先级 | 编号 | 需求 |
|---|---|---|
| **P0** | Q7-P0-1 | 产品源码 / `PHJ.html` **不得含**风格包 5 段与硬性要求原文；内置库限「通用能力 + 中性示例」 |
| **P0** | Q7-P0-2 | **零丢失**：升级不得静默删除用户本地已有的风格包；`state.cmpl.items` 若已含该资产必须保留；`恢复内置默认` 不得在无确认/无保留策略下清除用户导入的资产（见 US5） |

### 2.6 私有资产可用性方案方向（**UX 要求**；技术实现留给架构师）

**目标**：Holly 的日常使用零退化——「双击 `PHJ.html` → 风格包就在」。建议 **A + B + C 组合**：

- **A. 外部资产文件 + 一次性导入**：把风格包导出为独立小文件（如 `写作资产_风格包.json`）由 Holly 本机保存；工具内「导入写作资产」（**本地文件选择/拖入 → `FileReader`，无网络**）→ 写入 `state.cmpl.items`（localStorage）→ **此后永久本地留存**，日常无需该文件。（符合 R1/R3）
- **B. 降为「示例数据」**：内置仅留**明确标注「示例（请替换）」的中性占位**，机制可见但不含她的私有文本；她经既有 `补` 窗口替换为自己的内容。
- **C. 首启引导**：风格包组为空时给一条**非阻断**提示，告知可导入资产。

**必须满足的体验约束**：① 零丢失（P0-2）；② 零强依赖——单独双击可用（P0-4）；③ 零网络——本地文件读取（P0-3/R3）；④ **一次性成本**：允许一次导入，仅一次；⑤ **可发现**：入口/提示明确；⑥ **可携带**：支持导出/导入资产，不改源码。
