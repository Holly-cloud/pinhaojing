# 项目结构整理（2026-09-17）

> **类型**：决策记录（冻结）。
> **一句话**：把「一个 git 仓库裸放在工作区根」整理为「工作区合集 + 仓库内活文件/冻结记录/验收物证三分」，让每个文件都有**显式存在理由**。

## 1. 背景：整理前的 6 类问题

| # | 问题 | 具体表现 |
|---|---|---|
| 1 | **合集层无 README** | `AA_Dev/` 作为多项目工作区根，没有任何入口说明——陌生人不知道「这层是什么、各子项为何存在」。 |
| 2 | **`AA_Dev/` 根裸放资产文件** | `写作资产_风格包_v1.json` 直接躺在合集根，既不属任何项目、也不在仓库外资产区，定位含糊。 |
| 3 | **根 README 478 行、含 285 行版本史** | 交接入口里塞了 v6.0–v7.8 全部逐版功能现状，入口文档退化为版本台账，新人读不动。 |
| 4 | **dev 文档用编号当分类、`06_` 撞号三分** | `01_`–`11_` 平铺，编号只表时间不表类别；尤其 `06_` 下挤了「着色方案草案 / 小样截图 / 高亮小样」**三个不同产物**（撞号），检索与引用都别扭。 |
| 5 | **`_build/artifacts/` 三义混装** | 同一目录里同时放：**物证留档**（截图/语料）、**历史交接包**（`_recon_*`）、**可再生生成物**（`PHJ_test_v7.11.html`）——三种生命周期不同的东西混居，责任不清。 |
| 6 | **4 组逐字节重复文件** | 内容 sha256 完全相同的副本各存一份（详见 §4），白占体积、还制造「该引用哪份」的歧义。 |

## 2. 决策：目标结构

```

├── README.md                            【新建】合集入口：这层是什么 + 每个子项的存在理由
├── _assets/                             【新建】仓库外资产容器
│   ├── README.md                        【新建】为何刻意放在仓库外 + 怎么用 + 与仓库内文档的对应
│   └── 写作资产_风格包_v1.json           （从 AA_Dev/ 根 mv 进来）
└── pinhaojing/                          ← 项目仓库
    ├── .gitattributes   （改：路径规则）
    ├── .gitignore       （改：路径规则 + 路径无关保险丝）
    ├── PHJ.html         （不动）
    ├── README.md        （瘦身：478 行 → 入口文档）
    └── dev/
        ├── README.md                    （重写：开发入口总导览）
        ├── CHANGELOG.md                 【新建】版本沿革（承接从根 README 搬出的逐版功能史）
        ├── manifest.mjs                 （只改注释里的路径）
        ├── build.mjs                    （不动）
        ├── src/                         （完全不动）
        ├── docs/                        【新建】分类文档区
        │   ├── README.md                【新建】文档索引 + 分类存在理由 + 旧名→新名映射表
        │   ├── decisions/   拍板与决策
        │   ├── design/      设计与方案
        │   ├── releases/    发布与验收
        │   └── ops/         交接与演进
        └── _qa/                         （由 dev/_build/ 整体改名而来）
            ├── README.md                （重写：逐区域存在理由 + 分区表）
            ├── run-gate.mjs / lib/ / verify/ / diag/
            ├── snapshots/               闸门基准 + 历史快照（含 archive/）
            ├── records/                 （由 _qa/artifacts/ 改名）纯留档
            │   ├── README.md            【新建】每条留档「为哪份文档/哪个版本作证」
            │   ├── screenshots/         （合并原 artifacts/screenshots/ + artifacts/v78/）
            │   ├── corpus-20260913/     （由 画布语料_20260913/ 改名）
            │   └── archive/             （原 artifacts/archive/）
            └── gen/                     【新建】可再生产物（生成物，gitignore）
```

### 分区哲学（活文件 vs 冻结记录 vs 验收物证）

| 分区 | 性质 | 判据 |
|---|---|---|
| `dev/` 顶层（`README.md` / `CHANGELOG.md` / `manifest.mjs` / `build.mjs` / `src/`） | **活文件** | 每次改动都在变；是「当前事实」的唯一来源。 |
| `dev/docs/` | **冻结的历史记录** | 每份文档记录一个**已完成的**决策/方案/发布，写完即不再改（只加标注不删史实）。 |
| `dev/_qa/` | **验收工装 + 闸门基准 + 物证留档** | 可执行的工装 + 不可动的基准 + 只读的物证；`gen/` 单独隔离**可再生**生成物。 |

> **命名归位**：`_build` 名实不符（它不只是「构建产物」，更是**验收工装 + 基准 + 物证**的三合一），故改名 `_qa`。同时把「可再生生成物」从 `artifacts/` 里拖出来，隔离进 `gen/`；把「纯留档」集中到 `records/`。

## 3. 被废除的旧约定（如实记录）

1. **「版本快照一份都不能移」** → 收窄为「**只冻结闸门实际读取的基准**」。本次**仅删除内容逐字节重复的副本**（4 组），**不移位任何活基准**（当前快照 `PHJ_v7.13_*`、夹具源 `PHJ_v7.8_*`、各历史 argv 基准均原位保留）。
2. **「历史文档里的旧路径不跟着改」** → **保留**（对**冻结记录**继续有效），但**新增一条**：**任何活文档/README 不得引用旧路径**，权威映射表在 `dev/docs/README.md`。
3. **「文档用数字编号平铺」** → **废除**，改为「**分类目录 + 语义文件名**」；同案多件收进案目录（解决 `06_` 撞号）。
4. **「`_build/` 为构建资产目录」** → **废除**（名实不符），改名 `_qa/`；并把生成物隔离到 `gen/`、留档归入 `records/`、基准留在 `snapshots/`。

## 4. 影响面

### 4.1 改动的路径规则

| 文件 | 改动 |
|---|---|
| `.gitattributes` | `dev/_build/snapshots/**/*.html -text` → `dev/_qa/snapshots/**/*.html -text`（并补一行沿革注释）。**必须在任何 `git mv` 之前改**，否则快照会被按 `text=auto` 归一化，换机后闸门必红。 |
| `.gitignore` | ① `dev/_build/artifacts/写作资产*` → **路径无关**的 `写作资产*`（今后不依赖任何目录名）；② `dev/_build/artifacts/PHJ_test_*.html` → `dev/_qa/gen/`。 |

### 4.2 被改的 4 个脚本（唯一允许改代码处，逐处核对）

| 脚本 | 改动 |
|---|---|
| `dev/_qa/lib/test-artifact.mjs` | `ARTIFACT_DIR` → `gen/`；**删除 `ARTIFACT_VERSION` 常量**，产物名固定为 `PHJ_test.html`（从根上消灭「文件名里的版本号撒谎」）。 |
| `dev/_qa/verify/verify_build_equivalence.mjs` | `OLD` 默认值 `_build/snapshots/…` → `_qa/snapshots/…`；同步文件头注释与用法示例。 |
