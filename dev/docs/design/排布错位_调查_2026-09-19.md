# 需求②「重新打开工具后块间距不均」· 根因调查（2026-09-19）

> 性质：**只调查、不修代码**。对象 = 交付物 `PHJ.html` v7.17（288444 B / `state.version`=16）。
> 方法：自起自收 headless Edge + CDP，真机复现（脚本见文末「复现脚本」）；行号均为**实测**。
> 结论：**复现成功，判定为真 bug**（100% 稳定复现，5/5 次）。根因 = **画布块在 `display:none` 状态下被测量**，导致块高塌陷；与保存的 `y` 坐标叠加后**视觉间距不均**。

---

## 一、TL;DR（一句话根因）

**切到「画布」视图时，`setView()` 先调 `render()`、后调 `applyView()`（`view/write.js:211` → `:213`）；而此刻 `body` 仍带 `view-write` 类 → `.canvas{display:none}`（`styles/55-write.css:19,22`）。于是 `render()`→`autoSizeAll()`（`view/canvas.js:123`）在**元素不可见**时读 `scrollHeight`，读到 **0**，`autoResize()`（`canvas.js:101`）遂把每个 `.block-text` 的 `height` 写成 **`0px`** → 计算高度回落到 `min-height:84px`（`styles/10-canvas.css:13`）→ **所有块一律塌成 126px 高**。
由于块只存「左上角 `y`」、块高不落盘，**重开工具（默认落写作台）后一点「画布」就复现塌陷**；若此前用过「整」（`arrangeAll` 按真实块高把 `y` 排成均匀间距），塌陷后 `y` 间距不变、块高变小 → **视觉间距瞬间不均**。**

对照实证：**`load()` 时的首次渲染反而是正确的**——`wiring.js:296` 的 `load()` 在 `DOMContentLoaded` 之前执行，那时 `body` 尚无 `view-write` 类，`.canvas` 可见 → `autoSizeAll` 读到真实 `scrollHeight` → 高度正确。**唯独「用户点画布胶囊切过去」这一路径塌陷。**

---

## 二、现象 → 最小复现 → 证据

### 2.1 最小复现（稳定）

1. 打开工具（默认「写作台」）。点「＋ 新建分镜」建 3~4 个**内容行数不同**的块（如 1 行 / 5 行 / 12 行）。
2. 点顶栏「画布」→ 块全部等高（126px），**内容多的块文字被裁掉**。
3. 点「整」（左对齐整理）→ 此时块按**真实高度**排好，间距均匀（实测 `gaps=[24,24,24]`）。
4. **关闭并重新打开工具** →（回默认写作台）→ 点「画布」→ **间距变为 [24, 41, 197]（不均）**。

### 2.2 实测数据（脚本 `_diag_gap4.mjs`，同一会话内连续观测）

| 阶段 | 块 inline `height` | 块卡片高 `cardH` | `y` 间距 | 视觉 gap（块底↔下一块顶） |
|---|---|---|---|---|
| A 切到画布（`setView('canvas')`） | **0px ×4** | 126/126/126/126 | 150/150/150 | 24 / 24 / 24 |
| B 可见态重渲染（`render()`） | 104/123/279/104 | 126/143/**299**/126 | 150/150/150 | 24 / 7 / **−149（重叠）** |
| C 点「整」（`arrangeAll`） | 104/123/279/104 | 126/143/299/126 | 150/167/323 | 24 / 24 / 24 ✅均匀 |
| D **重开 + 点「画布」** | **0px ×4** | 126/126/126/126 | 150/167/323（不变） | **24 / 41 / 197 ❌不均** |

> D 行即 Holly 看到的现象：`y` 是「整」按**真实块高**排的（`y=[20,170,337,660]`），重开后 **块高塌成 126**，于是「块底→下一块顶」的空隙 = `yDiff − 126` = 24 / 41 / 197，**明显不均**。

### 2.3 调用点可见性探针（脚本 `_diag_gap5.mjs`，猴子补丁记录 `autoSizeAll` 被调瞬间的环境）

```
[setView('canvas') 触发的 autoSizeAll] → { bodyClass:"view-write", canvasDisplay:"none", firstScrollH:0   }
[render() 可见态  触发的 autoSizeAll] → { bodyClass:"view-canvas", canvasDisplay:"block", firstScrollH:104 }
```

→ **铁证**：走 `setView('canvas')` 时，`autoSizeAll` 明确在 `canvas display:none`、`scrollHeight=0` 下被调用。

## 三、根因（带文件:行号）

| # | 位置 | 事实 |
|---|---|---|
| ① | `dev/src/view/write.js:210-213` | `setView`：`activeView = v;` → `if(v==='canvas'){ render(); }`（**211**）→ `else{ renderWrite(); }` → `applyView();`（**213**）。**render 在 applyView 之前**。 |
| ② | `dev/src/view/write.js:58-72`（`applyView`） | 直到这里才 `body.classList.toggle('view-canvas'/'view-write')`。故 ① 期间 body 仍是 `view-write`。 |
| ③ | `dev/src/styles/55-write.css:19,22` | `body.view-write .canvas … {display:none}`（分组选择器，`.canvas` 在第 19 行，`display:none` 落在第 22 行）。 |
| ④ | `dev/src/view/canvas.js:8-32`（`render`） | 建卡 → `autoSizeAll()`（**25**）。 |
| ⑤ | `dev/src/view/canvas.js:123-129`（`autoSizeAll`） | 对每个 `.block-text` 调 `autoResize(tas[i])`（**126**）。 |
| ⑥ | `dev/src/view/canvas.js:99-102`（`autoResize`） | `ta.style.height='auto'; ta.style.height = ta.scrollHeight + 'px';`（**101**）。**隐藏时 `scrollHeight=0` → 写成 `height:0px`。** |
| ⑦ | `dev/src/styles/10-canvas.css:13` | `.block-text{ … min-height:84px; … }` → 塌陷后计算高度=84，卡片由把手段定高 → **126px**。 |
| ⑧ | 对照：`dev/src/shell/wiring.js:296` → `dev/src/core/persist.js:120-140`（`load`→`render`） | `load()` 在顶层执行（早于 DCL），此时 body 无 view 类 → `.canvas` 可见 → **首次渲染高度正确**。 |

**因果链**：`setView` 次序（①）→ 画布在渲染时被 CSS 隐藏（③）→ `autoSizeAll` 在隐藏态测量（⑤⑥）→ 高度写 `0px` → 全块塌成同高（⑦）→ 与「整」按真实块高烘焙的 `y` 间距叠加 → 视觉间距不均（§2.2 D 行）。

### 3.1 为什么「重新打开」必现、且只在「重新打开」被察觉

- `activeView` 是**会话态、不持久**（`core/store.js:22-23`，刷新回默认「写作台」）→ 重开必先进写作台 → 用户**必须点一次「画布」胶囊**才能看画布 → 这一点恰好踩中①的塌陷路径。**所以「重开后」是必然触发点**（在画布内直接停留时反而不塌）。
- 块高**不落盘**（`sanitizeState` 只存 `blocks` 的 `x/y/text/order`）→ 重开后高度从零重算 → 塌陷现象**每次重开都稳定重现**（非偶发）。
- `y` 落盘且不变（`migrate` 对合法数字坐标原样保留，见 §四）→ 间距「不均」来自**块高变了**，而非坐标变了。

## 四、逐一排查 team-lead 给的 4 个怀疑方向

### 怀疑 1：`migrate` 坐标兜底误判 → **不成立**
判据实测 = `typeof b.x === 'number' && typeof b.y === 'number'`（`core/persist.js:12`）。逐例喂 `migrate` 结果：
- 正常数字坐标 → **原样保留**（`x/y` 逐字不变）。
- `x/y` 缺失 / `null` / 字符串 → 回落 `gridPos(i)`。
- `NaN` → 经 JSON 往返变 `null` → 回落。
- **实测**：真实 UI 产出的块坐标恒为数字（`wdNew`/`addBlockHere`/拖拽/克隆/粘贴均写入 number）→ 正常使用**不会触发兜底**。故坐标不会在重开时跳变。

### 怀疑 2：`migrate` 按 `(hasOrd, ord, y, x, i)` 重排数组 → **只改数组顺序与 `order`，不动坐标**
实测（`_diag_gap.mjs` 场景 2）：画布双击建的 3 块，`migrate` 后 `x/y` **逐字不变**，仅**数组顺序**按 `y` 重排、`order` 重赋 0..N-1。数组顺序影响的是 **DOM 顺序=遮挡/绘制层叠** 与**写作台大纲顺序**，**不影响块的 `left/top`**，故**不产生间距变化**。

### 怀疑 3：`autoSizeAll`（`autoResize`+`fitBlock`）重开前后计算不同 → **★成立（就是本 bug）**
实测见 §2.3：`autoSizeAll` **在隐藏态被调用** → `scrollHeight=0` → 高度写成 0。这是**唯一**在「首建 vs 重开」之间真正变化的量。字体/量尺本身未发现二次差异（`textWidth` 用 canvas `measureText`，与可见性无关，宽度计算稳定）。

### 怀疑 4：`order`（写作台顺序）与 `y`（画布位置）互相污染 → **不成立**
实测（`_diag_gap.mjs` 场景 4）：写作台把第 3 条移到第 1 位（`wdMove(2,0)`）→ 仅 `order` 变（`k3:0,k1:1,k2:2`），`x/y` 不动；重开后 `x/y` 仍为 `20/20,20/170,20/320`。二者解耦。

## 五、修法建议（**本任务不改代码，仅建议**）

> ⚠️ 与需求③「多项目」正交：本 bug **应在多项目改造之前（或同时）修**，否则多项目切换项目时同样会在隐藏态渲染画布 → 同样塌陷（见需求③设计文档的风险清单）。

| 方案 | 位置 | 说明 | 评价 |
|---|---|---|---|
| **A（首选 · 一处）** | `view/write.js` `setView`（:210-213） | **把 `applyView()` 提到 `render()/renderWrite()` 之前**：即先切 body 类/显隐，再渲染 → `autoSizeAll` 在画布可见时测量。**或**在 `applyView()` 之后、`v==='canvas'` 时补一次 `autoSizeAll()`。 | 改动最小、语义最直；不动 CSS、不动数据结构。需复跑 W 组（W2 等读 computedStyle 的断言在 setView 完成后判定，应仍绿）。 |
| **B（加固 · 防复发）** | `view/canvas.js` `autoResize`（:99-102） | `if(ta.scrollHeight > 0){ ta.style.height = ta.scrollHeight + 'px'; }`（隐藏时不把高度写成 0，留待显示后重算）。 | 防「任何隐藏期渲染」再塌陷；需配「显示后必重算」的兜底（如 A 或下方 C），否则隐藏期只写 auto 不生效。 |
| **C（兜底）** | 进入画布后 | `requestAnimationFrame(autoSizeAll)` 或对 `#canvas` 挂 `ResizeObserver`/`transitionend` 触发一次重算。 | 额外保险；引入新监听需评估 R7（**不得新增 document/window 级 key 监听**——本方案不属 key 监听，合规）。 |

**推荐组合：A（必修）+ B（加固）**；C 视 QA 口径可选。修完建议 QA 新增一条常驻断言：**「设 3 个不同行数块 → 切画布 → 每块 `inline style height` ≠ 0 且 `cardH` 随行数递增」**（可证伪：把 A 改回原序即必红）。⚠️ 新增断言条数变动须先报 Holly 核准。

## 六、是否属真 bug / 附带发现

- **真 bug（真机稳定复现，5/5）**：是。属**渲染期测量时机**缺陷，**不损坏数据**（块高不落盘），但每次「重开→切画布」都会让块高塌陷、文字被裁、间距异常。
- **附带发现（独立问题，供 Holly 决策，非本调查结论）**：
  1. **写作台新建块用固定 `y` 步长 150**（`view/write.js:271-272`：`nb.y = ref.y + 150`），与内容行数无关；即便高度正确，长短不一的块在画布上**间距本就不均、长块还会叠住下一块**（§2.2 B 行 `gaps=[24,7,−149]`）。
  2. **`addBlockHere` / 粘贴块的 `y` 带 `((n%5)-2)*16` 抖动**（`view/modals.js:371`、`interact/paste.js:47`），多次双击建块呈不规则错位——这是**有意的错位摆放**，非 bug，但会加剧「不均」观感。
  3. `migrate` 对**合法但异常**的坐标不设上限（如极大/极小值原样保留）——目前无触发场景，仅记录。
