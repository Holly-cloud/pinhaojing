## 一、初衷复盘

### 1.1 你的原话（直接证据）

| 出处 | 原话 |
|---|---|
| 任务单 | 「想在独立文本编辑器弹出后，于**左右两边空白处**布置提升编辑效率的东西」 |
| 任务单 | 「连接即梦画布『补补补』取全部视频节点提示词 → **学习写作风格** → 研究如何让编辑器更高效（**至少降低重复劳动**）」 |
| 拍板 #2 | 「**不应该直接照搬数据，要从数据里研究规律**」 |

| 拍板 #4 | 「需要扩展：补个**更好的景别或镜头**」 |

| 拍板 #7 | 「点复制**直接把完整 text 送进剪贴板**」 |

### 1.2 反推：四条初衷

**① 消灭「重复劳动」中最大的一块 —— 项目级定型件**
不是泛泛地"提升效率"。53 条语料的实测数据把它量化了：`风格：` + 5 段属性 + 硬性要求 = **542 字符**，出现在 **44/53** 条里，占这类 prompt 的 **63%**；归一化后只有 **6 个变体**（23 条逐字相同）。
→ 也就是说：**你每条 prompt 有六成篇幅在重复同一段话**，而且因为手写/复制，产生了大量**复制漂移**（多空行、缺句号、残留 `>`、尾部粘了别的引用）。补全首先要解决的，是这 542 字符不该再打第二遍，而且**每一次插入都必须是干净的那一份**。

**② 从规律出发，而不是照搬数据 ★核心原则**
你明确否掉了初版方案（把 53 条原文做成候选表）。理由是：语料是**结果**，可复用的是**规律**。于是设计改为提炼出：
- 骨架 = **一组槽位**（53 条里分节顺序完全相同的只有 5 条 → 骨架是柔性的，不是模板）
- 原子单位 = **镜头句**（141 句，中位 66 字符，72% 含运镜词、55% 含台词）
- 词表 = **极小**（连接词 3 个、运镜 9 个、方向 2 个、台词动词 3 个）
- **唯一逐字引用的是风格包** —— 因为它是"项目级资产"，不是"镜头级文本"

这一条是整个功能的设计哲学：**规格化的是结构，不是句子**。

**③ 补全不只是"省力"，还要"扩展"**
你提"补个更好的景别或镜头"，落成了候选带 **"未用过"徽章** + 远近谱/动静谱。
依据同样是数据：标准运镜 15 词你只用了 3 个，景别 6 词只用了 3 个（远景/全景/大特写为 0），主观视角/平视/顶拍为 0。
更关键的一条发现：**功能型镜头术语（反应镜头/插入镜头/空镜）用词量为 0，却有 109 句"拍摄某人+表情/身体细节"的镜头句** —— 「你一直在拍反应镜头，只是用描述式写的」。
→ 所以补全要做的不是替你想，而是**让你看见自己写作的盲区**。

**④ 不打断写作流（贯穿全部实机反馈）**
回看 8 条实机反馈，全部是在为这一条让路：
`\` 在中文态出顿号 → 换 `#`（我不占键位）｜Tab 一键补全｜数字键直取（输入法式跳位）｜Esc 逐级退（第一次关候选、第二次才关窗口）｜鼠标点选用 `mousedown+preventDefault`（**保住焦点和光标**）｜气泡贴光标、下方不够自动上翻｜无候选时拦住 Tab（否则焦点逃逸、接着打的字全丢）。

**⑤ 附带的一条设计哲学：分层守住旧口径**
符号层（着色，零领域语义）／**结构层**（领域语义只活在 `STRUCT_MARKS` 一张表）／候选层。这个分层让 v7.6 的"引擎零领域语义"没有因为引入领域内容而破功 —— 后来在 R1（2026-09-17）直接演化成 `skin/` 抽取，成了「一套引擎 × N 套皮肤」的基础。

### 1.3 一句话总结初衷

> **把「你反复写的那六成」变成一次点击，把「你没想到要写的」摆到你眼前，全过程不离开键盘。**

## 三、改进建议（按 价值/成本 比排序）

### A.【高价值·低成本】修掉状态栏的"假错误" —— 按结构区豁免风格包
**依据**：v7.8 探查 B 第 7 条就实测过：中文逗号一律判错，而风格包用的是**另一套标点体系**（`、1540 ，968 ；352 。174`）。实测一条 1213 字符的 prompt 报 **22 处错误，其中约 18 处来自风格块**。
**现状**：`structMap()` 已经能标出 `region: 'style' | 'tail'`，但 `hlStatus()` 数错误时**完全没用它** —— 直接 `for(...) if(fam[i]==='err') errs++`。
**做法**：复用 v7.7「台词区豁免」的**同一机制**（错误计数与着色同源，按 region 过滤），把风格区/硬性要求区的 `，` 移出错误族。
**收益**：状态栏的「N 处错误」恢复可信。这是写作时的**信心指示器** —— 常年挂 18 处假错误，人就会彻底无视它，真错误也看不见了。

### B.【高价值·中成本】让「未用过」变成活的 —— 用你自己的文本当真相
**依据**：初衷 ③。而 `corpus.js` 里 `note: '未用过'` 是**写死的字符串** —— 你今天用了"推镜"，明天徽章还在。
**做法**：扫当前编辑器文本（或全部块）统计词表命中，**动态生成**徽章。存量数据已经够了：`cmplActive()` 就是词表，`structSummary`/文本扫描就是统计器。
**收益**：「扩展」引导永远是准的，用过的自动消失、没用过的持续提示。**不需要新增任何数据字段**，真相来自你的写作本身。
**延伸**：同理可做「本节还没用过 X」的上下文提示。

### C.【高价值·低成本】把 `CMPL_GROUP_HINT` 挪出引擎 —— 它是"皮肤可换"的破口
**事实**：`complete.js:20` 有一张**领域中文**映射表：
```js
var CMPL_GROUP_HINT = { 风格包:'style', 硬性要求:'tail', 起手式:'anchor', 结构件:'mark', 镜头句:'body', 景别:'body', 运镜:'body', 台词:'body' };
```
它躺在**引擎层**（`editor/**`），用于"按当前节置顶"（`cmplBuildGroups:204`、`cmplScore:242`）。
**两个问题**：
1. **违约 R1**：R1 承诺「换皮肤 = 换 `skin/corpus.js`，引擎零改动」。但只要换一套皮肤，新皮肤的组名**不被这张表认识** → **结构感知置顶直接失效**，而这恰恰是拍板 #3 的核心能力。
2. **已经脱节**：表里的 `硬性要求: 'tail'` 是**失效映射** —— 语料里没有叫「硬性要求」的组（它只是"风格包"组下的一条 item）。
**做法**：把「组名 → 节 region」的映射搬进 `skin/corpus.js`（与 `CMPL_GROUPS` 同处，作为语料的一部分），引擎只负责读取。
**收益**：兑现 R1 承诺；顺带把「风格包/起手式」等词元从引擎代码里挪走，**降低 R3-A 棘轮压力**（当前 15 个命中词元中就有它们）。

### D.【高价值·中成本】加"最近使用"权重 —— 直击"重复劳动"
**依据**：初衷 ①。而"重复"本身就是**频次信号** —— 你反复用的那几条，是最该浮上来的。
**现状**：组内（`cmplBuildGroupItems`）与查询结果（`cmplBuild`）都只按生效表顺序 + 命中质量排，**没有任何使用数据**。
**做法**：`state.cmpl.use = { key: { n, t } }`，排序时加权（频次 × 衰减）。
**收益**：补全池从"静态语料"变成"**跟着你的习惯长**"。这是投入产出比最高的一条增强。

### E.【中价值·低成本】兑现或删除 `CMPL_PER_GROUP`
**事实**：`complete.js:17` 定义 `CMPL_PER_GROUP = 4`（注释写"无查询时每组先露几条"），但**全项目零引用**；`cmplBuildGroups` 里预览条数是**硬编码的 3**，且只拼成一行纯文本。
**二选一**：
- 兑现它 —— 组视图直接平铺"该组前 N 条"（少一次"进组"操作，更接近拍板 #6 说的"量大先展开候选组"的意图）
- 或删掉死常量，避免误导后来人

### F.【中价值·低成本】给 `structSummary()` 找到归宿 —— 写作台左栏「节」徽标
**事实**：`struct.js:75` 定义了 `structSummary()`（整篇结构摘要），**全项目零调用**；`PHJ.struct` 只导出 `structAt`。原设计文档标注"供后续检查器/侧栏用"——**至今没人用**。
**时机**：v7.15 刚交付的**写作台**正是它的天然归宿 —— 左栏每条显示「节」徽标（起手式/分镜 1/风格包/硬性要求），或给一个"整篇结构体检"（哪些节缺失、风格包是否在位）。
**收益**：把拍板 #3「结构要能明确提示」从**状态栏一个格子**扩展成**整篇可见**。与写作台 PRD 的 P1-10 直接接上，几乎零新增机制。

### G.【中价值·中成本】资产导入的静默截断要提示
**事实**：候选池硬上限 —— 组视图 `slice(0,24)`、组内 `slice(0,40)`、查询 `slice(0,24)`；数字键只覆盖 `1..9`。而 `cmplApplyAsset()` 允许导入成百上千条。
**风险**：超出上限的候选**静默消失**，用户以为"导进来了"，实际看不到。
**做法**：超限时在气泡底部加一行「还有 N 条 · 继续输入以缩小范围」。

### H.【构想·高成本·最贴合初衷】从"你自己的写作"里发现规律
**依据**：初衷 ② 的原话 ——「**不应该直接照搬数据，要从数据里研究规律**」。
v7.8 时"数据"是 53 条历史 prompt。但现在数据源已经变了：**你正用这个工具写新分镜**（写作台 + 画布）。
**可做**：
- **高频句发现**：统计你反复手打的句子/n-gram → 提示"要不要收进片段库"（把"从数据里学"变成**持续**的）
- **结构漂移检测**：风格包又被手改出第 7 个变体了 → 提示统一
- **盲区持续追踪**：见 B
**收益**：把补全从**一次性学习**（2026-09-13 那 53 条）升级为**持续学习**。这是最贴合初衷、也最能放大这套设计价值的方向。

### I.【小】配置窗口的槽位校验
`${n}` 靠手写，易错（写成 `$1` / `${a}` / 跳号）。建议：编辑卡片加"插入槽位"按钮 + 保存时校验编号连续。
