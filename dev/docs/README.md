# dev/docs/ · 文档索引（分类历史记录区）

> 本目录 = **冻结的历史记录**：每份文档记录一个**已完成的**决策 / 方案 / 发布，**写完后不再改**（只在必要时加「⚠️ 已撤销」标注，不删史实）。
> 与 `dev/` 顶层「**活文件**」（`README.md` / `CHANGELOG.md` / `manifest.mjs` / `build.mjs` / `src/`）的分工：**活文件每次改动都在变；本目录只增不改**。
> **当前现状**一律以 `dev/_qa/snapshots/BASELINE_v7.14.md` 与根 `README.md` 为准。

## 一、四个分类，各一句存在理由

| 分类 | 记什么 | 一句话存在理由（删了会怎样） |
|---|---|---|
| `decisions/` | **为什么**这么定（已拍板的立项、工程计划、重构路线、需求变更） | 没有它，后人只看见「现在长这样」，看不见「当时为什么否掉了别的路」。 |
| `design/` | **怎么做的方案**及其小样 | 没有它，方案一旦落地就只剩代码，评审过程与取舍（含被否方案）全丢。 |
| `releases/` | **做成了什么**（发布说明与验收记录） | 没有它，每个版本的验收口径与交付范围无法追溯。 |
| `ops/` | **怎么交接、往哪走**（换机指南、目标架构与长期规划） | 没有它，换机与后续路线只能靠口头传授。 |

## 四、命名与归档约定

1. **语义文件名**：文件名自带「主题 + 版本/日期」；不再用数字编号平铺（旧的 `01_`–`11_` 编号即「按时间」，撞号问题见 `decisions/项目结构整理_2026-09-17.md`）。
2. **同案多件收进案目录**：如 `design/着色方案_v7.6-v7.7/` 收纳「方案 + 小样截图 + 高亮小样」——同一案子的多个产物不再撞号。
3. **只增不改**：本目录文档写完即冻结；被撤销的决策就地标注「⚠️ 已撤销」，不整段删除。
4. **活文件不得引用旧路径**：任何活文档/README 必须引用上表「整理后」列；旧路径只允许出现在本目录这类**冻结记录**里。
