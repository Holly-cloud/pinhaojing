## 4. 使用说明（极简主路径）

1. **双击** `PHJ.html` → 浏览器打开即用
2. 顶栏：`⇩ 整理`（所有块自上而下左对齐，视角归零）｜ `⭳ 导出` ｜ `⤒ 导入`
3. 画布：**双击空白**新增块（落在双击处）；**拖块把手**摆放；**拖空白**平移视角；**滚轮**上下滑动；点空白取消输入焦点
4. 块宽**随内容自适应**：最长的一整行完整显示、不自动换行；块内文本多行照常（换行符保留）
5. 拼接栏底部：`＋ 存为模板`（当前拼接 → 自定义单元预设，命名模态框）｜ `模板 ▾` 展开列表 → **套用**（清空当前拼接、替换为模板内容）/ **改名** / **删除**（可撤销）
6. 数据自动保存于本机浏览器（localStorage），重要分镜定期「导出」硬备份

## 5. 已知边界

- 数据存于 file:// 域 localStorage，浏览器清理策略可能清除 → 用「导出」硬备份
- 超长行（约 >900px 宽）块会超出画布右缘：画布 overflow:hidden，超宽部分不可见，可用「整理」后滚轮查看（未做横向滚动，属需求范围外）
- 套用模板在画布新建的块会与原块重叠（错位 +28）：可点「⇩ 整理」一键排布
- 目录名仍为「分镜提示词管理面板」：改名「拼好镜」时被进程占用（`Device or resource busy`），需关闭占用进程后手动重命名（README 已记录）

排查发现 3 条会吞掉多选的路径（v6.1 遗留）：

| 场景 | 根因 |

> 交付物：`PHJ.html`（61KB，v6.4）；v6.3 原版备份 `_build/PHJ_v6.3_20260909.html`

## ① Ctrl+V 粘贴建块

- **paste 事件**监听（无需剪贴板权限）：焦点不在输入区（块 textarea / 模态框 / 拼接栏气泡）时 Ctrl+V → 剪贴板**整段文本**创建为一个新块，落在**视口中心**（连续粘贴逐次错位）；空剪贴板忽略；toast「已粘贴为块（N 字符）」
- 输入区内粘贴完全保留原生行为

## ② 模板系统重构（前缀/后缀单元）

**数据模型**：`templates: [{ id, name, prefix, suffix, items[] }]`——模板单元拥有**前缀值**与**后缀值**（均可空），容纳多个 prompt 块。示例映射：

- 顺带查实（影响口径的正例/反例）：JSON 式 `{"a":1, "b":2}` 的 `,` 位于引号**之间**（栈内无引号）→ 不会被误豁免；半角引号奇偶错乱时以最新开启的那个为界（既定 toggle 语义）；跨行对白在换行处重置栈 → 第二行不继承台词区（与拍板②一致）。

## 2. 技术方案：叠层高亮（overlay）

```html
<div class="blk-edit">
  <pre class="blk-hl" aria-hidden="true"><code id="blkHl"></code></pre>  <!-- 彩色层（含行号）：只显示，不接收事件 -->
  <textarea class="blk-input" id="blkInput"></textarea>                  <!-- 编辑层：文字透明、光标可见 -->
  <div class="blk-status">行/列 · 字符 · 错误数 · UTF-8 · LF</div>        <!-- 状态栏 -->
</div>
```

- **两层排版声明必须逐字一致**（`font-family/size/line-height/letter-spacing/tab-size/padding/white-space/overflow-wrap`）——共用同一条选择器组声明，杜绝漂移

- 彩色层：`pointer-events:none`；`scroll` 事件 + `ResizeObserver` 同步尺寸与滚动（保住原 `resize:vertical` 行为）
- 渲染：`hlClassify()` 逐字符分类（配对栈，O(n)）→ 逐行输出（行号 + 族色 + 错误 + 配对底色）；输入/光标/移除空行三处接线重渲染

# v7.4 修复（2026-09-11）—— 拼模式虚影位置错位

> 触发：Holly 实机反馈**「虚影位置错位 没有在鼠标位置」**（v7.3 引入）
> 交付物：`PHJ.html`（133.6KB，v7.4）；v7.3 构建件 `_build/PHJ_v7.3_20260911.html`；诊断工具 `_build/diag_ghost_offset.mjs`

## 根因（量化定位）

虚影用 `card.cloneNode(true)` 克隆原块 DOM —— **`cloneNode` 会连原块的 inline 样式一起复制**，其中包含 `left/top`（块的画布坐标，如 `200px/150px`，由 buildCard 写入）。
而 **inline style 优先级高于 CSS 类规则** —— `.block-ghost{left:0;top:0}` 的归零被 inline 覆盖。

**量化证据**：

| | ghost inline left/top | ghost 实际左上角 | 鼠标位置 | 偏差 |
|---|---|---|---|---|
| v7.3（修复前） | `200px / 150px`（原块坐标） | (877,498) | (700,400) | **(177,98)** ❌ |
| v7.4（修复后） | `0px / 0px` | (677,348) | (700,400) | **(23,52) = 抓取偏移** ✅ |

> 修复后的 (23,52) 正是「鼠标按下点相对块左上角」的抓取偏移 —— 即虚影从原块位置被"拿起"、保持相对光标的关系，与拖动真实块的手感一致。

## 修复内容

`createGhost()` 中显式归零/清空克隆带出的 inline 属性：`left/top = 0`、`transform = ''`、`transition = none`、`transitionDelay = 0ms`（width/height 本就显式覆盖）。

- **D2f2**：虚影 inline 定位已归零（`left/top = 0px` 且 `position: fixed`）

## 教训（已写入技能）

**`cloneNode(true)` 会复制 inline 样式**（含 `left/top/transform` 等定位属性），而 inline 优先级高于 CSS 类规则 → 用克隆做「虚影/幽灵元素」时，必须显式归零所有继承来的 inline 定位属性，不能指望 CSS 类覆盖。

## 教训（已写入技能）

**给高频 JS 驱动的元素（拖拽目标）加 CSS `transition: transform` = 摧毁跟手性**：JS 每帧写 transform 会被过渡逐帧缓动。规则：跟手路径上的元素，拖拽态必须 `transition:none`；hover 类过渡只能作用于「非拖拽态」。可复用的量化诊断法：鼠标移位后**立即**读元素 rect 与期望位置对比（v7.1 实测滞后 115px、修复后 2px）。

## 技术设计（动效层）

- **只动 transform + opacity**（GPU 合成零重排）；光线生长用 SVG stroke-dashoffset（合成属性）；box-shadow 动画仅 hover 级小面积
- **曲线体系**（联网收集的行业基准）：进入=decelerate `cubic-bezier(0,0,.2,1)`；离开=accelerate `cubic-bezier(.4,0,1,1)`；叙事排布=premium ease-out `cubic-bezier(.16,1,.3,1)`；反馈≤200ms、叙事≤350ms
- **红线保持**：拖拽/平移/缩放跟手 0 延迟（拖拽路径不挂 transition）；不新增任何 UI 控件；数据模型零改动（version 12 保持）；rAF 既有循环不碰
- **无障碍**：`@media (prefers-reduced-motion:reduce)` 全部动效降级直切（`animation:none`）——无 UI 开关，跟随系统设置
- 体积：116.0KB → 120.8KB（增量 +4.75KB / 4.1%），在预算（≤7KB）内
